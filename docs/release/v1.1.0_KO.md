# v1.1.0 Getting on Track

> 상태: 릴리스 노트. 공개 상태와 산출물은 GitHub 기록 참조
> 갱신: 2026-11-13
> 언어: awaiting native review(원어민 검토 대기)

다른 언어: [English](v1.1.0.md) · [简体中文](v1.1.0_ZH.md) · [日本語](v1.1.0_JA.md)

작성자는 다음 안정 본체 버전으로 **v1.1.0 Getting on Track**을 선택했으며, 함께 제공되는
**AMF 0.4.0 Beta**(본체 `>=1.1.0, <2.0.0` 필요)는 Beta 단계를 유지하며 호환 범위 안에서 독립적으로 업데이트됩니다.
Getting on Track은 *Factorio*에서 첫 기관차를 제작하는 업적 이름에서 가져왔습니다. 안정 버전은 본체의 수명 주기를 뜻하며,
아래 검수 대기 항목과 제한 사항은 그대로 적용됩니다.

## 설치와 업그레이드

Windows x64 파일은 **VUA-1.1.0-windows-x64-setup.exe**(온라인)와
**VUA-1.1.0-windows-x64-offline.exe**(런타임 포함)입니다. 공개된 파일은
[v1.1.0 GitHub 릴리스](https://github.com/VUA-Project/VUA/releases/tag/v1.1.0)에서 받습니다.
[공식 미러](https://ph-r.com/vua/downloads/)에는 현재 제공하는 버전이 표시됩니다. 설치 파일에는
Authenticode 서명이 없어 처음 실행할 때 Windows가 경고할 수 있으며, 업데이트 출처는 릴리스 매니페스트의
Ed25519 서명으로 확인합니다.

1.0.0이나 0.7.0에서 올릴 때는 진행 중인 작업을 마치고 시스템 트레이 아이콘을 포함해 VUA를 종료한 뒤, 정식 공개된 1.1.0
설치 파일을 실행합니다. 검증된 동일 버전 Electron 런타임은 재사용하면서 본체와 AMF를 함께 업데이트합니다.
AMF 0.4.0은 1.1.0 본체의 확장된 제작 흐름, 로컬 SDK 테스트, 외부 도구 연결, 상품 정보 보강 인터페이스를 사용하므로
본체 `>=1.1.0, <2.0.0`이 필요하며 1.0.0 본체에 단독 모듈 업데이트로 제공되지 않습니다. 기존 `%APPDATA%\VUA`
데이터는 유지되며 깨끗한 VM에서의 업그레이드 검증은 대기 중입니다.

## 1.0.0 이후의 변경

- **새로운 네이티브 Windows 설치·제거 화면**: 여러 단계의 기존 NSIS 마법사를 Per-Monitor DPI v2 지원 단일 카드형
  네이티브 화면으로 교체했습니다. 시스템 다크/라이트 모드와 Windows 기본 표시 언어 우선순위(`en`, `zh-CN`, `zh-TW`,
  `ja`, `ko`)를 따르고, 앱 실행 중 잠금이나 네트워크 오류 시 제자리 다시 시도와 설치 완료 후 자동 실행을 지원하며
  `/S`, `/ISOLATED`, `/D=` 옵션을 그대로 유지합니다.
- **시작 속도 개선, 설치 용량 절반 축소, 압축 업데이트**: 가벼운 정적 시작 화면, Main과 본체 Provider 병렬 초기화,
  초기 화면 안정 후 AMF 지연 실행, `VUA.Runtime.exe` 하드링크 공유, 병렬 해시 검증 및 실행기 인계, 런타임 외 라이선스
  고지 정리, 서명된 `windows-distribution v0.3` zstd 압축 패키지를 통해 설치 용량을 약 875 MiB에서 약 450 MiB로 줄이고
  실행 대기 시간을 단축했습니다.
- **목적 중심 시작 화면과 외부 도구 연결**: 시작 화면(`scenario-environment v0.2`)에서 3개 소셜 플랫폼과 15개 구성·기기 항목(데스크톱 화면,
  SteamVR PC VR, PICO 스트리밍, 독립형 헤드셋 스토어 플레이)을 고르면 필요한 준비 단계를 조합해 안내합니다. 외부 도구 연결에 `external-tool v0.4`
  Steam 항목과 `installer-tool v0.1` 공식 설치 프로그램 안내를 추가했습니다.
- **Avatar Optimizer, 로컬 SDK 테스트, Recipe v0.6**: 선택형 `com.anatawa12.avatar-optimizer` 단계와 NDMF 클론
  지표(`amf-production 0.43.0`, `unity-bridge-v5 0.24.0`), 검증된 초안 미리 채우기와 구버전 이전을 지원하는 Recipe 관리 및
  `amf-recipe v0.6`(`0.1.0`), 로컬 Avatar SDK 테스트 빌드와 업로드 가능 여부 관찰(`amf-production-flow v0.1`)을
  추가했습니다. 작업용 Unity 프로젝트를 지워도 완성된 Avatar의 미리보기 이미지를 유지합니다.
- **대규모 라이브러리 읽기 가속, BOOTH 실제 구매 시각, 상품 정보 보강**: 읽기 캐시와 전용 읽기 스레드로 소재 스캔 중에도
  약 110 ms 수준으로 응답합니다. ‘최근 추가’는 BOOTH 주문 페이지의 실제 구매 시각을 따르며 보유 상품의 요약 관찰 정보를
  보강합니다(`catalog-enrichment v0.1`).
- **서명된 가이드 채널, 업데이트 안전성, 다섯 언어 UI 다듬기**: 내장 폴백을 갖춘 `guide-content v0.1` 서명 채널,
  철회되었거나 호환되지 않는 구성 요소 업데이트의 안전한 처리, 첫 실행 안내 확인 이후로 늦춘 자동 업데이트 확인 및 7일 로그
  보관/`Asia/Shanghai` 일별 집계(설치 ID 없음) 고지, 창·설치 프로그램 표시 이름의 `VUA` 단일화, 다섯 언어 문구·백과사전·최소 안내서와 Grid, Aero, Tenshi, Jirai
  네 테마의 대비·배치 개선을 포함합니다.

## 확인 대기와 제한 사항

번체 중국어를 포함해 **다섯 UI 언어 모두 원어민 검토 전**입니다. 자동 배치·조작 검사는 언어 검토를 대신하지 않습니다.

빌드 도구에는 저장소 내부 패턴을 처리하는 [minimatch 서비스 거부 보안 공지](https://github.com/advisories/GHSA-g3hv-75wg-m249)가
남아 있으며(제품 실행 의존성에는 없음), PDF 글꼴 처리는 구체적 취약점 지적이 없는
[유지보수 종료 공지](https://rustsec.org/advisories/RUSTSEC-2026-0192.html)가 붙은 `ttf-parser` 0.25.1을 계속 사용합니다(교체는 후속 작업).

작성자의 검사를 임의로 생략 또는 통과 처리하지 않았습니다. 다음 검사가 남아 있습니다.

| 작성자 확인 대기 | 아직 검증되지 않은 부분 |
| --- | --- |
| SDK 로그인, 로컬 Avatar SDK 테스트 빌드, 실험적 VRChat 로그인과 Avatar 목록 | 1.1.0 후보 버전의 실제 계정·실제 SDK 테스트 동작 |
| 실제 Unity 라이선스 오류 후 안내와 복구 | 합성 검사만으로 Editor 복구를 입증할 수 없음 |
| 기록한 깨끗한 Windows VM에서 1.1.0 네이티브 온라인·오프라인 설치 및 제거 | 새 설치, 제거 및 실기기 화면 캡처 |
| Steam(`v0.4`) 및 공식 설치 프로그램(`v0.1`) 도구를 미설치부터 설치·실행까지 확인 | 감지·실행 픽스처는 새 설치 확인을 대신하지 못함 |
| 1.0.0/0.7.0 업그레이드, GitHub 차단 후 중국 본토 미러 `v0.3` 압축 업데이트 | 데이터 보존, 런타임 재사용, 미러 `v0.3` 전송 실측 |
| F4: 감싼 폴더·낱개 파일·중첩 모음을 포함한 실제 라이브러리 | 작성자의 모든 파일이 빠짐없이 기록되는지 |
| F5: P-02 예측·Avatar Optimizer 지표와 빌드 결과 비교, F6: 제작 중 제목 표시줄 | 허용 오차, 최적화 지표와 실제 자원 표시 비교 |
| F7: VRCFury가 들어 있는 실제 의상 | 실제 소재에서의 감지 |
| F8: 깨끗한 VM에서 최소 안내서 수행, 첫 사용·UI의 사람 검토 | 추가 도움 없이 완주 가능한지와 사용성 |

공유 링크는 중국 본토 시험 서버를 계속 사용하므로 다른 지역에서는 접속되지 않을 수 있으며, 실패 시 오류를 표시합니다.
지역 지연은 HTTP 참고값으로 VRChat 방의 Ping이 아닙니다.

공개 뒤에는 [AMF 커뮤니티 검사 목록](../development/freeze-plan.md#4-amf-checks-by-the-community)(복잡한 소재, Poiyomi,
Avatar Optimizer, 얼굴 추적, 병렬 제작, 이용 조건, Recipe 재현 등)을 확인하고 본체·AMF 버전과 개인정보를 뺀 결과를
[GitHub 이슈](https://github.com/VUA-Project/VUA/issues)에 남겨 주세요. 인증 정보, 주문 내역, 유료 소재 파일은 로컬에 보관합니다.

## 빌드와 검수

AMF UI ABI는 **amf-ui/0.1**, application/Bridge는 **0.1**, BDL 쓰기는 **0.11**, 읽기는 **0.1–0.11**입니다.
관련 문서 버전은 amf-production **0.43.0**, unity-bridge-v5 **0.24.0**, ai-tools **0.15.0**,
amf-recipe **v0.6 (0.1.0)** 및 **v0.5 (0.2.1)**, recipe-selection-draft **0.2.0**, scenario-environment **v0.2 (0.1.0)**,
external-tool **v0.4 (0.1.0)**, installer-tool **0.1.0**, guide-content **0.1.0**, catalog-orders **0.1**,
catalog-enrichment **0.1**, library-view **0.3.0**, library-maintenance **0.3.0**, 라이브러리 이전 **0.1.0**, 이용 조건 **0.3.1**,
AMF UI runtime/data recovery **0.1**, Windows distribution **0.1 / 0.2 (0.3) / 0.3 (0.1)**입니다.
전체 목록은 선택한 소스 시점의 [REGISTRY](../REGISTRY.md)를 참조합니다.

릴리스 소스는 변경 불가 [v1.1.0 태그](https://github.com/VUA-Project/VUA/tree/v1.1.0)로 식별합니다.
공개된 `release-manifest.json`은 정확한 커밋, `vua-release.json`은 서명된 페이로드 목록, `SHA256SUMS.txt`는
공개 파일의 해시를 기록합니다. CI 결과는 해당 PR에 있습니다. 공개만으로 N 단계 검수나 위 실제 실행이 완료되지는 않습니다.
